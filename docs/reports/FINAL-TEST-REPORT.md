# تقرير الاختبار النهائي للفرونت إند (قبل التسليم للباك إند)

**التاريخ:** 13 نوفمبر 2026
**النسخة:** فرع PR #17 (المراحل 0 لـ 8) + إصلاحات الاختبار ده (PR منفصل فوقه)
**طريقة الاختبار:** نسخة production (`npm run build` + `npm run start`) في وضع البيانات التجريبية (mock)، ومتصفح Chromium حقيقي بيتحكم فيه Playwright كأنه مستخدم: بيعمل تسجيل دخول بالكود، ويفتح الصفحات، ويضغط الزراير، وينزل الملفات.

---

## الخلاصة في سطرين

الموقع شغال كله في كل الأكونتات وكل الصفحات، من غير أي error في الكونسول ولا صفحة بتقع ولا حاجة بتخرج بره الشاشة على الموبايل.
لقينا 3 مشاكل واتصلحوا، وكل التستات عدّت بعد الإصلاح. الفرونت إند جاهز يتسلم للباك إند.

### السيناريوهات الكاملة (E2E) اللي عدّت على اللابتوب والموبايل

- تسجيل الدخول بالكود: كود غلط، قفل الأكونت بعد محاولات، أكونت موقوف، الكود يفضل بعد تغيير اللغة أو الثيم أو الريفرش.
- الحجز: اختيار خط ومحطة ← رفع الإيصال ← المالية توافق ← الكارنيه يظهر (QR بيتغير كل 30 ثانية).
- تغيير الخط: الطالب يطلب ← ولي الأمر يوافق ← إدارة النقل توافق.
- تصريح المجسم (من غير موافقة ولي الأمر)، الاسترداد بالجدول والمستندات، الشكاوى والرد عليها.
- "مش هروح النهارده" ورحلاتي.
- يوم الرحلة: السواق يبدأ الرحلة ويمسح كارنيه سيف ← أبوه والمكتب يشوفوا إنه ركب، تبليغ تأخير.
- SOS: طبي ← العيادة تستلمه وتسجل الإسعاف؛ عطل ← النقل يبعت باص بديل؛ السوبر أدمن يشوف بس من غير ما يتصرف.
- المخالفات: المشرف يسجل ← شؤون الطلاب تقرر.
- التقارير: كشف المشتركين، الحضور، إشغال الكراسي — Excel و PDF اتنزلوا واتفتحوا والعربي سليم.
- مواعيد العودة: النقل يغير ميعاد خط 7 ← سيف يشوفه.
- باصات الفعاليات مع أبو الهول، المستخدمين وسجل العمليات.
- تغيير اللغة عربي/إنجليزي في نفس المكان من غير شاشة تحميل والأسامي بتتغير معاها.
- الوضع الفاتح والغامق، ومفيش أي صفحة بتتحرك بالعرض على الموبايل.

### بعد أول زيارة (الموقع متسطب كـ PWA)

الـ Service Worker بيحفظ الملفات، فكل صفحة بتفتح في **حوالي 0.4 ثانية** ومن غير ما ينزل أي ملف تاني.
على النت العادي (من غير تبطيء) متوسط فتح الصفحة كان **0.8 ثانية** والأبطأ 2 ثانية، ودخول أي أكونت حوالي 1.5 ثانية.

**ملحوظة:** الأرقام دي في وضع البيانات التجريبية، والـ JS فيه السيرفر التجريبي وبياناته. في وضع live الحجم هيقل، والسرعة الحقيقية هتعتمد على سرعة رد الـ API.

## 4) حاجات معروفة ومش أخطاء

- **النهارده جمعة:** مفيش رحلات، فصفحات الرحلة والـ SOS بتقول "مفيش رحلات النهارده" وفيها زرار **"جرّب يوم تجريبي"** في وضع الديمو.
- **صفحة المساعد الذكي** عند الطالب مكتوب عليها "قريبًا"، لأنها شغل فريق الـ AI.
- **PDF التقارير** في الديمو بيتعمل في المتصفح كصور (كشف 689 طالب = 23 صفحة ≈ 5 MB). في النسخة الحقيقية الباك إند هو اللي يعمل الملف.
- بعض الشكاوى والطلبات التجريبية مكتوبة بالإنجليزي لأنها كلام الطالب نفسه، مش ترجمة الموقع.
- **أماكن المحطات** لسه تقريبية لحد ما مكتب النقل يبعت المواقع الحقيقية. وميعاد محطة مسجد بلال في خط 19 محتاج تأكيد.

## 5) المطلوب من فريق الباك إند

1. **العقد:** `frontend/openapi.json` (اتعمل بـ `npm run openapi`) + ملف الاتفاق `SUtech-Frontend-Backend-Agreement` (عربي وإنجليزي). كل endpoint موجود مرة واحدة في `src/features/*/api.ts` ومعاه الـ errors بتاعته.
2. **التشغيل مع السيرفر:** `NEXT_PUBLIC_API_MODE=live` و `NEXT_PUBLIC_API_BASE_URL=<عنوان FastAPI>` و `NEXT_PUBLIC_MAP_TILE_URL` (مزود الخرايط المعتمد). الـ build بيرفض يكمل لو `NEXT_PUBLIC_API_MODE` مش متحدد.
3. **الجلسة:** في live لازم تكون **HttpOnly cookie** (الفرونت مبيحفظش التوكن). 30 يوم للطلبة وأولياء الأمور والطاقم، و12 ساعة للمكاتب.
4. **الصلاحيات:** الفرونت بيخفي اللي مش مسموح، بس **السيرفر لازم يمنع** هو كمان: كل دور يشوف بياناته بس، والسوبر أدمن عرض بس على أبو الهول والعيادة/الطوارئ (يرجع 403).
5. **الـ WebSocket** (`bus.location`، `trip.status`، `sos.new`، `sos.update`): لحد ما يتعمل، الفرونت بيعيد القراءة كل 10 ثواني. لما يتعمل لازم عنوان `wss://` يتضاف في `connect-src` في `next.config.ts`.
6. **التقارير:** Excel و PDF يتعملوا على السيرفر (roster / payments / attendance / seat_occupancy).
7. **التواريخ والفلوس:** التواريخ ISO بتوقيت UTC، والفلوس بالقرش، والـ errors بالشكل `{code, message}`.
8. **الحضور:** `GET /admin/attendance` لازم ياخد `line_id` موجود؛ الفرونت بياخد أول خط من `GET /admin/lines`.

## 6) إزاي تعيد الاختبار بنفسك

```bash
cd frontend
npm ci
npm run check                                     # typecheck + lint + format + knip + unit tests
NEXT_PUBLIC_API_MODE=mock npx playwright test     # بيعمل build ويشغل الـ E2E على لابتوب وموبايل
```

الكود التجريبي بيظهر في شاشة الدخول نفسها في وضع الديمو.
