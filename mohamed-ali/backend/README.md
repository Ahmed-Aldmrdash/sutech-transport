# SUtech Transport Backend

Initial FastAPI foundation for the SUtech Transport API. This folder contains only shared application infrastructure; feature endpoints and business rules belong to their assigned backend owners.

## Requirements

- Python 3.11+
- PostgreSQL 18

## Local setup

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
docker compose up -d db
alembic upgrade head
uvicorn app.main:app --reload
```

The API is served under `/api/v1`. Open `/docs` for the generated OpenAPI documentation, `/api/v1/health/live` for the process health check, and `/api/v1/health/ready` to check database connectivity.

## Database migrations

Create a migration after adding ORM models:

```powershell
alembic revision --autogenerate -m "describe the schema change"
alembic upgrade head
```

Review autogenerated migrations before committing them. The application does not create or alter tables automatically at startup. Model modules added under `app/modules/*/models.py` are discovered by Alembic.

## Shared conventions

- API prefix: `/api/v1`
- JSON field names: `snake_case`
- Error response: `{ "code": "UPPER_SNAKE_CASE", "message": "..." }`
- Database operations use async SQLAlchemy sessions. Routes/services own transaction boundaries and explicitly commit successful writes.
- Add feature routers under the assigned folder in `app/modules/` and include them from `app/api/v1/router.py` after coordinating the route and schema with the team.
- Follow [CONTRIBUTING.md](CONTRIBUTING.md) for module ownership and the shared-file workflow.
- See [LEGACY-MODEL-REUSE.md](LEGACY-MODEL-REUSE.md) before copying any model from the earlier backend draft.

Authentication, authorization, business endpoints, AI chat, and feature models are intentionally not included in this foundation.
